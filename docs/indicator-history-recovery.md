# 指标历史恢复与影子实验重验

状态：2026-10-31 本地已实施、测试及离线重验；未发布，未修改或重启线上服务。

## 恢复契约

- 已收盘OHLCV完整历史、最近信号、账户与逐笔台账存于同一个production_state.json检查点。每根收盘处理成功后，以临时文件、flush/fsync、原子替换方式提交；无成交也提交。
- 同一根收盘内的现货调仓与合约变更只在整根处理结束后提交；处理中抛错或写入失败会停止处理，磁盘保留上一个完整检查点。已有日志、成交导出和看板快照不是账户恢复依据，异常时以主检查点及健康状态为准。
- 启动先验证、恢复检查点中的完整历史并重算指标；恢复完成后不对同一根收盘重复调仓。重复轮询不再追加同一根K线。
- paper模式逐根补齐停机期间的已收盘K线；日熔断使用处理K线的收盘UTC日，而不是重启当天。实盘模式不补发历史订单，遇到需要补跑的历史收盘停止处理，等待对账。
- 历史缺口、损坏、非有限OHLCV、未收盘时间、写入失败均不再触发截短预热。超过接口可返回范围的停机缺口会停止，需要有依据的连续历史恢复。
- 完整历史会随时间增长；本次不裁剪历史，以免再次改变EMA起点。

## 旧状态与迁移限制

没有indicator_history的旧状态只能进行一次标记为legacy_bootstrap的冷启动；这不保证与旧进程的指标连续。不能把旧账户与任意新取299根历史拼起来声称已经修复。

本次生成的reconstructed_checkpoint.json仅为本地、对应取证时点的迁移候选。它由原主账户完整状态增补经重验的377根历史构成，保留4笔合约平仓、13笔现货调仓和3笔开仓事件。它没有安装到服务器。

未来发布前必须重新采集同一收盘时点的账户、health和历史并核对；不得把本次旧时点候选覆盖到已继续运行的账户。主服务和影子实验分别保留备份，另建派生实验目录；不改写原实验。

## 影子读取与验证

源账户含检查点历史时，run_shadow.py直接使用该历史，不再二次请求公开行情来替代策略输入。现有实验的历史前缀与源检查点不一致时拒绝推进，不覆盖余额或自动重置实验。旧状态没有指标历史时，账户即使数值相同也不再标记comparison_validated=true。

离线工具仅接受本地文件，不连接服务器、不调用订单接口：

```bash
.venv/bin/python scripts/revalidate_shadow_history.py \
  --source-db /path/to/read-only-original.sqlite3 \
  --online-state /path/to/production_state.json \
  --online-health /path/to/production_health.json \
  --output-directory /path/to/new-output-directory \
  --reset-before 2026-10-18T00:00:00Z --history-bars 299
```

reset-before是旧重启后第一根新K线的**开盘UTC时间**；本例旧重启发生于北京时间10月18日10:30。此参数只用于有日志依据的旧行为重建，不是新策略规则。

工具拒绝已存在的输出目录。它只读备份原数据库、保存原主状态和health、记录输入SHA256，在continuous和restart_aligned两个新子目录回放。只有账户、收盘时点、逐笔现货、实验恢复、主检查点恢复和完整旧台账验证均通过才保留迁移候选。缺乏历史的旧主状态必须提供health末根收盘证据。
