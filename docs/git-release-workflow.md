# Git 发布流程

本项目按“本地修复与测试 → 提交 → push 到 GitHub → 服务器拉取同一提交 → 构建与发布 → 验收”的顺序交付。不得把直接上传本地文件作为常规发布方式，也不能把服务器工作区或页面已更新当作 GitHub 已同步。

1. 本地检查工作区、目标分支和远程最新状态。提交明确范围的代码、测试及文档，排除密钥、`.env`、账户状态、交易日志、数据库和生成文件。
2. 执行相关测试，记录提交 SHA，push 到已确认的远程分支；回读远程 SHA，确认推送成功。当前 GitHub 默认分支为 `btc_danyizhongcang`，不要凭习惯改用或创建 `main`。
3. 服务器先只读检查 HEAD、工作区、运行容器、配置及账户。存在未提交或服务器独有内容时，先比较、备份和保全；不得强制覆盖或硬重置。
4. 确认服务器修改已被远程提交包含后，保留工作区快照，使用 `git pull --ff-only origin <目标分支>` 同步。无法快进或存在内容冲突时先查清原因。
5. 核对本地、GitHub、服务器 HEAD 一致，并检查实际构建源文件。获得发布授权后才构建和部署；运行镜像要能追溯到提交 SHA。配置、账户和持仓不随源码拉取被替换。若运行代码已与提交一致，只做 Git 对齐，无需重复重启。
6. 分别报告 Git 同步、镜像/服务、账户连续性、API、真实页面和下一次自然策略评估的验收状态。保存备份和回退材料；有新自然成交后，不得盲目恢复旧账户状态。
